PRxCDB... persisted reactive context database...

PRxCDB is the name given to the db that covers the cookies, secure cookies, session storage and so on. Now there are 3 versions of this.

  • siloed, meaning if you are in a forgiving enviroment this sets up the db in a way where the entirety of the system I am about to go over, is in its own silo.
  • react, meaning that you can drop this into any react based system and it is 100% compatible. Its hooks do not follow reacts rules on hooks, as you can place them in module space, in loops and in conditions... and they fucking work with zero collisions with reacts on hooks.
  • then we close it out with the normal version. While this version is still 100% accessible through the bus... Maybe it is because I have worked in too many enviroments that are just harsh and hostile. But this version is entirely decoupled from the bus and can be accesssible on its own AND through the bus as well since it does not have any reuirements in order to use it. This is the version that will be the default in the_wizard platform

PRxCDB comes FULLY with an entire system that allows its hooks to be reactive in any enviroment. Meaning... the hooks found inside and are accessible in the system... actually are reactive in nature. Each call site except for reacts... which... I might change... but I might not because I will never use a react system again. But each call site comes with a boolean that you can toggle to trigger a render event... or not.

Siloed is literally a single file that can be dropped into any application... easy as pie. The react version is also like this.

The default is spread over 5 files. The global context is also entirely decoupled... BUT is still accessible the same way through PRxCDB which is accessible through the bus. The reasoning for this is because in apps where you NEED access and control DURING the init phase, this grants that you. Where as the other two do not.

Note

SAURONS GLOBAL CONTEXT

As far as your concerned... think of this platform feature essentially... fucking right off and abondoning us, haha.

But... you will be happy about, who it was that we called in to fill in for that asshole. Instead of an in memory globally accessible context registry. In warlock mode only, it will entirely be replaced with the buses distributed reactive crdt state.

In effect, while yes... the context system already removed the file semantic boundary for us... but this takes it a step further.

Before now, whenever you code something... at runtime, whatever or where ever or whenever that piece of code needs to be accessed and executed or its value acquired, the app essentially only takes a static snapshot of it... and relays that same snapshot over and over and over again.

What this does instead, is we first take a carbon copy of it and make a 'mimic' of it and placing it in its own boxed, non pollutable storaged container. These will stay there unless called upon, at which point we can copy and write over... the currently live mutatable version that is avialable for everything to use.

By making every thing mutatable by design, where not only do you have the decision to mutate it at the original defining call site... but also each and every other single node, you can decided to have it ALSO mutate that compnent or function and replace what it currently is at the time of updating it.

If you are worried about the code running away from you... you can always call upon the mimic, copy it and overwrite the mutatable version any time you want. Whether that happens at a threshhold you set that can be triggered... or maybe you would rather do it on a timer... who cares it your code, do whatever you want. BUT we now have that power, that has never been seen in development before.

Caution

Right now, the way a user uses websites, its as if... they knock on one door of one house, ie loading a webpage... and whenever they want to go to the enxt... they literally walk up to the next house and knock on the door again... ie, everything is thrown adn then entire page is gotten from the site and rebuilt and re rendered... state is redone... all the values from the db is redone... it is fucking wasteful

Instead, there should be... 'portals' that are entirely transparent so that you can view the underlying portals behind it... so one portal will be the sidebar/layout portal... the next will be the navbar, the footer, the header, the pages on page sidebars for navigational... all the way down to... the actual pages body where the body is rendered.

AND each portal stacks on top of eachother... so whenever a user click on a link on another page... it does NOT change out literally the whole page... EVERYTHING stays the same...

  • the sidebar
  • the state
  • the already scquired db values
  • everything currently already rendered along with its states in all their forms... EXCEPT... the actualy body of the page itself...

OVERVIEW

Essentially a meta-programming context-passing container system using JavaScript/TypeScript Proxy objects and global registries.

By leveraging two-pass execution (Pass 1 with stubs to collect shape/constants, followed by Pass 1.5/Pass 2 with live resolution via proxies) and a global registry mirror (NexusMirror), this has bypassed traditional static file-import constraints.

I have completely replicated the behavior of a class—and go beyond it—by letting the functions dynamically cross-reference each other's evaluated results globally without explicit imports.

How this System Mimics and Extends Classes In a classical OOP language, a class encapsulates state and behavior, and instances can reference other instances or static context. The implementation maps directly to these concepts:

Traditional TypeScript classes are static, isolated, and strictly bound by file-import hierarchies. But the wizards Incantations architecture already solves the exact problems classes fail at:

  1. Circular Independence via Stubs (makeStub): While standard classes crash or throw initialization errors if they circularly reference each other, your multi-pass system safely handles it by passing proxy stubs during the first pass and binding live values in the second.
  2. Global Cross-Wiring (NexusMirror & KERNEL_REGISTRY): Instead of manually importing CSEAdapter, MetricsPornStar, or other singletons everywhere, your system automatically mirrors everything registered across the kernel. Any function or component can peer into any other component's space natively.
  3. Your lowest level lets you define single instances (Incantations), and your higher levels (Incantations_lvl2, Incantations_lvl3, Incantations_vars) let you orchestrate multiple instances and complex state scopes within a single macro factory.

TOGGABLE FEATURES

THE FOLLOWING FEATURES CAN BE SWITCHED ON/OFF DEPENDING ON YOUR PREFENCE AND USE FOR THEM. WITH DEVELOPMENT, EVERYTHING COMES AT A COST WHEN IT COMES TO ADDED FEATURES AND THE PERFORMANCE THEY REQUIRE. INSTEAD OF JUST FORCING YOU TO HAVE THESE FEATURES ENABLED, ALL THE TIME AND WITH IT THE PERFORMANCE COST, YOU MAY SET THESE VALUES AS YOU WISH AT ANY TIME IN THE INIT CONFIG.

  • DEV TOOLS: WHILE THE DEV TOOLS IS ONLY EVER ACTIVE WHILE YOU HAVE A DEV TOOLS SIDEBAR FOCUSED, BUT IF YOU NEVER USE IT AT ALL YOU CAN JUST SIMPLY TURN THEM OFF.
  • WIRE TAPS: THIS IS DIFFERENT FROM THE SELF REFERENCING VALUE IN EACH PRIMITIVE. WIRE TAPS ALLOWS WHATEVER IT IS RETURNED... TO BE AVAILABLE ANYWHERE FROM WITHIN THE APP. IN ADDITION TO THAT, YOU MUST ALSO SUPPLY IT WITH A USER DEFINED LABEL, THIS IS TO ENSURE NOTHING IS HAPPENING WHEN YOUR NOT EVEN USING IT.
  • PARASITE MODE: THERE ARE PRIMITIVES THAT CAN LITERALLY CONSUME ONE ANOTHER AND TAKES ITS DEFINED FUNCTION, AS ITS OWN. ALLOWING IT TO NOW REFERENCE THE CONSUMED FUNCTIONS DEFINED VALUES, FUNCTIONS AND OBJS AS IF IT WERE THEIR OWN THROUGH THE SELF VALUE.

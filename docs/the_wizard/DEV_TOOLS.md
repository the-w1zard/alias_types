### THE HOW
Now, you are probably looking at this and saying, fucking hell that is a lot of data to be fucking throwing around... ALL THE TIME. It won't... First, there already is a boolean in the init config that allows you to turn on or off this entire feature app wide and is even already coded into the primtives so that nothing happens if turned off. 

Secondly and more importantly, the effect scopes, primitives and whatever else... will only be actively producing dev tool data... IF YOU HAVE THE DEVTOOL SIDEBAR OPEN. Which makes it so that, even if you have dev tools enabled, they will still not produce anything unless you are currently looking at the sidebar. While sometimes yes, devtools do get a lot of use, but how much time... DO WE ACTUALLY spend in that dev tool on a on going basis. Since that answer has too many variables to account for, I have made it so that, unless you have that sidebar open... it will not produce data and in effect will not create a bunch of unneeded noise whenever you don't even need them. The nice thing about it is, other then having to toggle a boolean, beyond that there are no other added steps or processes to our job in order to gain the benefits that dev tools provide. Since any and all required steps that would be needed, have been coded in such a way that they just react off of us simply opening the dev tool in the sidebar.

I'm hoping this ends up not just being the most sophistaced tooling available... but also just the easiest to use.

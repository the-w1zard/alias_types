    // If you do not know who venom is, he is a character in marvel comics and is a alien symbiotic lifeform. At will, venom can consume whatever tickles his fancy and in effect obsorbs or gain all of its hosts abilities, strengths, etc of what it is that he is being a parasite of...
    // Quite LITERALLY, that is EXACTLY what the platform primitive named... 'Venom', does in terms of its capabilties. In its stock form... it can't really do much, BUT it can consume what it wants, when it wants and where ever it is that the original platform primtive was defined. 
    // Now... once consumed, EVERYTHING that was defined in the host primitive... Venom now has the exact same functionlity and values as if he had coded them into the primitive himself. 
    // The other unique characteristic about his feature set is that... once he HAS consumed something... at that point he can actually use the consumed values and function and build off of them and create other functions within himself.
    // For example, if you have venom consume... lets say 7 platform primitives, where it cherry picked out of ALL the defined functions within the app... so that he can create a specialized component required for use in some part of the app.
    // ... this allows for an ENTIRE new workflow... where it is SO much more organized. THINK ABOUT IT... If you planned your platform primitives, properly for the first time in our careers where... ANYTHING AND EVERYTHING USER RELATED... goes into a single fucking location and no where else...     // Well, instead of littering... user shit there... user settings here... more user things over yonder... venom comes into play... making it so that, each semantic grouping... STAYS EXACTLY WHERE THE FUCK IT BELONGS... While STILL gaining access to the required functions we would need to take care of this section of the app. Venom runs around... being an asshole parasite and takes what he gained and creates... more specialized functionality NEEDED AND REQUIRED FOR THAT SECTION OF THE APP... SO WE HAVE THE BEST OF ALL WORLDS... 
    // 1. Semantic purity preserved — User logic stays in user group, auth stays in auth group, settings stays in settings group. None polluted.

    // 3. Zero duplication — No copy-pasting functions across sections.
    // 4. Zero waste — Every line of code serves exactly one purpose, consumed exactly where needed, built upon precisely when required.
